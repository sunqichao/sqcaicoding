# Code Review 评分标准

> 阶段 4 使用。**AI 自审 → AI 自优化 → 人工终审**，迭代 3~5 轮收敛。
> 人工**不逐行看**，只看高风险处。

---

## 一、四个审查维度

### 维度 1：功能逻辑（40 分，权重最高）
- 业务逻辑与 `.ai/docs/<需求名>/01-requirement.md` 是否**逐条一致**
- 边界条件、异常流程、并发场景是否覆盖
- 是否存在"看起来对、实际会算错"的逻辑（**重点：涉及金额 / 资损的计算**）

### 维度 2：代码设计（25 分）
- 分层是否正确，职责是否单一
- 是否复用既有抽象，而非另造一套
- 依赖方向是否符合宪法

### 维度 3：代码质量（20 分）
- 明显缺陷、资源泄漏、N+1、死代码
- 空值 / 异常 / 超时是否处理

### 维度 4：代码规范（15 分）
- 是否命中 `CLAUDE.md` 红线
- 命名、日志、事务、错误码是否符合 `coding-standards.md`

---

## 二、报告格式

```markdown
# Code Review 报告（第 N 轮）

## 总分：__ / 100

| 维度 | 得分 | 说明 |
|---|---|---|
| 功能逻辑 | /40 | |
| 代码设计 | /25 | |
| 代码质量 | /20 | |
| 代码规范 | /15 | |

## 严重问题（必须修）
1. [文件:行] 问题 → 影响 → 建议

## 一般问题（建议修）
1. ...

## 高风险提示（请人工重点确认）
- 涉及金额 / 资损的逻辑
- 边界 case、并发、幂等
- 安全敏感点（越权、注入、敏感信息）
```

## 三、评分锚点（参考实测）

| 水平 | 分数 |
|---|---|
| 首次一次性生成的典型水平 | 70 分左右 |
| 迭代 3~5 轮后的目标 | ≥ 95 分 |
| 前端（5 分制）首次 | 约 4.3 分 |

---

## 四、闭环规则

1. 报告出具后，**立即按"严重问题"清单自行优化代码**，重新自审，出下一轮报告
2. 每轮应比上一轮得分更高；**连续两轮无提升则停止并上报人工**
3. **人工终审只看三处**：高风险提示清单、严重问题是否真修、边界 case
4. 若问题**属于规范缺失**（而非本次代码失误），回改 `references/*.md`
   —— 这是整套方法复利的核心：规范越积越厚，同类错误不再犯
