# 编码规范

> 阶段 3 使用。**规范里不含任何业务逻辑**——这样才能全团队复用一套。
> 与项目 `CLAUDE.md`（宪法）冲突时，以宪法为准。

---

## 零、通用原则

1. **先对齐宪法**：动手前确认代码落在正确的分层与目录，宁可少写也不能放错位置
2. **不引入新依赖**，除非需求明确要求且已在宪法中登记
3. **最小改动**：修改类需求不得顺手重构无关代码；确需重构的单独记录并说明
4. **产出即完整**：不留 `TODO`、不留空实现、不假装完成
5. **同步产出过程文件**：DDL、接口文档、变更说明，不留到事后回补

---

## 一、后端分层规范

按宪法定义的分层，逐层约束：

| 层 | 职责 | 禁止 |
|---|---|---|
| 接口层（Controller） | 参数校验、DTO 转换、鉴权 | 写业务逻辑、直接调数据层 |
| 业务层（Service） | 业务规则、编排、事务边界 | 拼接 SQL、处理 HTTP 细节 |
| 数据层（DAO / Mapper） | 单表 / 有限联表查询 | 业务判断 |

- **事务**：加在业务层方法上，禁止跨远程调用持锁
- **异常**：统一异常类型 + 错误码；**错误码与错误消息必须分开定义**，禁止在代码里拼接文案
- **日志**：入口 / 出口 / 异常点必打，含 traceId；禁止日志出现敏感数据
- **空值**：明确空语义，禁止用 null 表达多种含义

## 三、注释与命名

- 注释只解释"为什么"，不解释"是什么"
- 命名风格与既有代码一致；新概念必须先在术语表中定义
