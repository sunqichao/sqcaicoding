# 编码规范

> 阶段 3 使用。**规范里不含任何业务逻辑**——这样才能全团队复用一套。
> 与项目 `CLAUDE.md`（宪法）冲突时，以宪法为准。

---

## 零、通用原则

1. **先对齐宪法**：动手前确认代码落在正确的分层与目录，宁可少写也不能放错位置
2. **不引入新依赖**，除非需求明确要求且已在宪法中登记
3. **最小改动**：修改类需求不得顺手重构无关代码；确需重构的单独记录并说明
4. **产出即完整**：不留 `TODO`、不留空实现、不假装完成
5. **同步产出过程文件**：DDL、接口文档、变更说明，不留到事后回补

---

## 一、缺口门禁（动手前必过）

> 目的：把"盲写再返工"变成"先确认再动手"。Agent 带着缺口开写，返工成本远高于现在多问一句。

**Step 1：逐项自检**（每项给出 PASS / FAIL，FAIL 必须写明缺什么）

| 检查项 | 通过标准 |
|---|---|
| 接口 / 契约 | 依赖的上下游接口、入参出参、错误码已明确（或已在需求中定义） |
| 字段 / 数据 | 涉及的表、字段、类型、取值范围、存量数据兼容方式已明确 |
| 权限 | 谁能调用、数据可见范围、越权场景已明确 |
| 状态机 | 状态集合、合法流转、终态与回退已明确 |
| 边界 | 空值、超限、并发、幂等、失败重试已有结论 |
| 验收 | 每个功能点有可验证的验收标准 |
| 约定 | 宪法 / 既有代码里有可参照的同类实现 |

**Step 2：处理结果**
- 全部 PASS → 进入编码
- 存在 FAIL → **输出缺口清单**（缺什么、影响哪个功能点、建议由谁补），**不得带缺口开写**；缺口并入待澄清列表，交人补齐

**Step 3：谁来做的成本判断**（缺口较多或任务本身高度依赖隐性知识时）
> Agent 总成本 = 准备成本（补上下文）+ 验证成本 + 返工风险
- 上下文齐备、有同类实现可参照、有验证手段 → 交给 AI 执行
- 补缺口 + 验证的成本接近或超过人直接做 → **建议人来做**，AI 只负责辅助（出方案、写测试、审查）

## 二、后端分层规范

按宪法定义的分层，逐层约束：

| 层 | 职责 | 禁止 |
|---|---|---|
| 接口层（Controller） | 参数校验、DTO 转换、鉴权 | 写业务逻辑、直接调数据层 |
| 业务层（Service） | 业务规则、编排、事务边界 | 拼接 SQL、处理 HTTP 细节 |
| 数据层（DAO / Mapper） | 单表 / 有限联表查询 | 业务判断 |

- **事务**：加在业务层方法上，禁止跨远程调用持锁
- **异常**：统一异常类型 + 错误码；**错误码与错误消息必须分开定义**，禁止在代码里拼接文案
- **日志**：入口 / 出口 / 异常点必打，含 traceId；禁止日志出现敏感数据
- **空值**：明确空语义，禁止用 null 表达多种含义

## 四、注释与命名

- 注释只解释"为什么"，不解释"是什么"
- 命名风格与既有代码一致；新概念必须先在术语表中定义
